Security & Architecture Overview

An honest, transparent look into how Invoice-Gen.net protects customer data, isolates client-side documents, secures authentication, and safeguards infrastructure.

1. Account & Authentication Security

User accounts are secured using industry-standard cryptographic techniques in our Node.js runtime. We do not store plaintext passwords under any circumstances.

Salted SHA-256 Hashing Every password is hashed with a unique 32-byte cryptographic salt generated via crypto.randomBytes before database persistence.
HttpOnly Session Cookies Session tokens are stored in strict HttpOnly cookies inaccessible to client-side scripts, neutralizing Cross-Site Scripting (XSS) session theft.
Google OAuth Token Validation Google authentication tokens are verified against Google's official identity endpoints before account creation.

2. Relational Database & Data Isolation

Customer data is stored in an embedded SQLite database using Write-Ahead Logging (WAL) mode for fast, atomic transactions and complete relational data integrity.

Parameterized Queries All database queries use prepared statements with strict parameter binding, completely eliminating SQL Injection vulnerabilities.
Scoped User Isolation Every invoice, client, and file lookup enforces a mandatory user_id foreign key constraint to ensure users cannot view or modify others' data.
Cascading Deletes Foreign keys are enforced (PRAGMA foreign_keys = ON). When an account is deleted, associated invoices, clients, and activity logs are permanently purged.

3. Guest Mode & Client-Side PDF Generation

For visitors using Invoice-Gen.net without creating an account, your sensitive business data is completely isolated to your device.

Zero-Server Guest Drafting Guest drafts, line item prices, customer names, and bank accounts remain strictly in your browser's private LocalStorage sandbox.
Client-Side Vector Engine Vector PDFs are generated locally in JavaScript memory using client-side engines. No document payload is transmitted across the internet.
Instant Local Purge Clicking 'Reset Form' or clearing browser cookies instantly destroys all locally cached invoice drafts.

4. Payment Security & Tokenization

When utilizing optional payment links or checkout integrations:

No Cardholder Data Stored Credit card numbers and bank credentials never touch our web servers. Payments execute through direct tokenization with Stripe and PayPal.
Static Payment Hyperlinks Payment links embedded on invoices use standard HTTPS URLs (e.g. Stripe Payment Links, PayPal.me, or direct bank transfer numbers).

5. Infrastructure & Transport Security

All web traffic between your browser and Invoice-Gen.net is protected by Transport Layer Security (TLS 1.2 and TLS 1.3) with modern cryptographic cipher suites. Private file attachments and API endpoints enforce strict session route guards.
